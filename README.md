# Центр-Строй

Демонстрационный интернет-магазин строительных товаров. Проект показывает полный сценарий покупки: поиск и выбор товара, корзину, регистрацию, оформление доставки и обработку заказа в панели управления.

Приложение работает в браузере и публикуется как статический сайт. Текущая версия использует демонстрационный каталог и локальное хранение данных; серверная часть, реальная оплата и подключение к учётной системе магазина не реализованы.

## Возможности

- **Каталог:** 93 модели, 100 товарных вариантов, 8 категорий. У вариантов отдельные артикулы, фотографии, характеристики, цены и остатки.
- **Поиск и фильтры:** название, артикул, характеристики, категория, производитель, цена, наличие и комплектация. Сортировка по цене, названию и наличию.
- **Корзина:** изменение количества, выбор комплектаций и проверка доступного остатка.
- **Аккаунт:** обязательная регистрация или вход перед оформлением, профиль, автозаполнение контактов и история заказов. Можно указать другого получателя.
- **Получение заказа:** самовывоз или доставка по Крыму, включая Севастополь. Адрес выбирается нажатием на интерактивную карту; дом и квартиру можно уточнить вручную.
- **Учёт остатков:** при оформлении количество списывается, при отмене возвращается однократно. Заказ сохраняет состав и цены на момент покупки.
- **Управление магазином:** создание и редактирование товаров, варианты, цены, остатки, загрузка фотографий, архивирование и восстановление, просмотр заказов и изменение статусов.
- **Адаптивный интерфейс:** поддержка компьютеров и телефонов, закреплённые действия покупки и оформления на мобильных экранах, управление с клавиатуры и учёт настройки уменьшения анимации.

## Технологии и устройство проекта

| Компонент | Технология |
| --- | --- |
| Интерфейс | React 19, TypeScript 7 |
| Разработка и сборка | Vite 8 |
| Стили и графика | CSS, SVG, локальные шрифты и фотографии WebP |
| Интерактивная карта | Leaflet 1.9 |
| Хранение состояния | localStorage, IndexedDB |
| Автоматические тесты | Vitest 5 |

Компоненты интерфейса используют общее состояние через React Context. Операции с корзиной, создание заказа, проверка остатков и смена статусов вынесены в отдельную модель. Карта загружается отдельным модулем при выборе доставки.

```text
src/
  components/       Каталог, карточки товаров, корзина, оформление, аккаунт, админка
  data/             Демонстрационный каталог и географическая зона доставки
  App.tsx           Основной интерфейс и переходы между разделами
  Shop.tsx          Общее состояние приложения и сохранение изменений
  model.ts          Типы данных, корзина, заказы, остатки и статусы
  storage.ts        Хранение загруженных фотографий в IndexedDB
  delivery.ts       Расчёт стоимости доставки и интеграция с маршрутизатором
  delivery-map.ts   Проверка координат и определение адреса
  styles.css        Стили и адаптивная вёрстка
assets/             Исходные изображения, шрифты, иконки и SVG-графика
scripts/            Подготовка и синхронизация ресурсов
public/             Статические файлы для публикации
```

## Локальный запуск

Требуются Node.js 22.12 или новее и npm. Установка использует версии из `package-lock.json`.

```sh
npm ci
npm run dev
```

Адрес приложения выводится в терминале; по умолчанию — `http://localhost:5173`. Перед запуском и сборкой локальные ресурсы автоматически копируются из `assets/` в `public/media/`.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Сервер разработки |
| `npm test` | Автоматические тесты |
| `npm run build` | Проверка TypeScript и сборка в `dist/` |
| `npm run preview` | Локальный просмотр собранного сайта |

## Публикация

После `npm run build` содержимое `dist/` можно разместить на статическом хостинге или веб-сервере. Node.js на сервере публикации не требуется.

В Vite настроены относительные пути (`base: './'`), поэтому сайт можно разместить в подкаталоге. Разделы открываются внутри приложения без отдельных URL; настройка SPA fallback не требуется. Для работы локальных аккаунтов нужен HTTPS или localhost: обработка паролей использует Web Crypto API.

Каталог, фотографии и шрифты входят в сборку. Для картографической подложки, определения адреса и внешнего расчёта маршрута требуется интернет.

## Карта и расчёт доставки

При выборе доставки пользователь отмечает точку на карте. Приложение проверяет её принадлежность сухопутной зоне Крыма и Севастополя, определяет адрес и сохраняет координаты в заказе. Проверка географической зоны выполняется также при создании заказа.

Используемые источники:

- **OpenStreetMap:** картографические тайлы с отображением авторства; [условия использования](https://operations.osmfoundation.org/policies/tiles/).
- **Photon:** обратное геокодирование, то есть получение адреса по координатам; [описание сервиса и условия](https://photon.komoot.io/). Повторные ответы кешируются в памяти, частые нажатия объединяются, устаревшие запросы отменяются.
- **Natural Earth:** географические полигоны зоны доставки; [источник и условия использования](src/data/delivery-area.LICENSE.md). Генерализованный контур может немного отличаться от точной береговой линии.
- **OpenRouteService / HeiGIT:** необязательный расчёт автомобильного маршрута от магазина до выбранной точки.

Без ключа маршрутизатора используется демонстрационная таблица расстояний. Стоимость — `ceil(расстояние в км × 2 ₽)`; для населённого пункта вне таблицы применяется условное расстояние 120 км. Такой результат подписан в интерфейсе как условный и не учитывает точный адрес.

При подключённом маршрутизаторе расстояние округляется вверх до целого километра, а выбранные координаты передаются напрямую. При недоступности маршрутизатора приложение возвращается к явно обозначенному условному расчёту. Изменение адреса или точки сбрасывает предыдущий расчёт. Тариф и исходную координату магазина перед реальным использованием нужно согласовать с магазином.

### Переменные окружения

Для настройки скопируйте `.env.example` в `.env.local`, задайте необходимые значения и перезапустите сервер разработки либо пересоберите сайт.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `VITE_ORS_API_KEY` | Ключ OpenRouteService; без него расчёт условный | Не задан |
| `VITE_ORS_BASE_URL` | Базовый адрес API маршрутизации | `https://api.heigit.org` |
| `VITE_MAP_TILE_URL` | Шаблон адреса картографических тайлов | `https://tile.openstreetmap.org/{z}/{x}/{y}.png` |
| `VITE_PHOTON_BASE_URL` | Базовый адрес совместимого геокодера Photon | `https://photon.komoot.io` |

Переменные `VITE_*` встраиваются в клиентскую сборку и доступны в браузере. Секретные ключи следует хранить на сервере; для этого потребуется серверный прокси. Публичные картографические сервисы имеют ограничения нагрузки и доступности; для рабочего магазина нужен подходящий тариф провайдера или собственная инфраструктура.

## Данные и ограничения демоверсии

Каталог, корзина, аккаунты и заказы сохраняются в `localStorage` под ключом `centr-stroy-demo-v1`. Загруженные фотографии хранятся в IndexedDB (`centr-stroy-images`); изображения обрабатываются в браузере и сохраняются в WebP.

Данные доступны только в том браузере и на том домене, где они созданы. Между вкладками одного домена изменения синхронизируются; общей базы для разных покупателей и устройств нет. Очистка хранилища браузера удаляет локальные данные. Экспорт JSON содержит структурированные данные, но не включает загруженные фотографии из IndexedDB.

Регистрация обязательна в демонстрационном сценарии. Пароли хешируются с индивидуальной солью через PBKDF2, однако серверная авторизация и разграничение доступа отсутствуют. Демо админка открыта для демонстрации. Следует использовать вымышленные контакты и отдельные тестовые пароли.

Оплата имитируется: банковские данные не запрашиваются, деньги не списываются. Заказы не передаются магазину, письма и SMS не отправляются. Цены, остатки и ассортимент демонстрационные. Права и источники фотографий, шрифтов и иконок описаны в [реестре ресурсов](assets/README.md).

## Проверка качества

Автоматические тесты проверяют корзину и варианты товаров, ограничения количества, списание и возврат остатков, сохранение состава заказа, обязательную авторизацию, поиск и фильтрацию, хеширование паролей, границы зоны доставки, определение адреса и взаимодействие с маршрутизатором.

Внешние API в автоматических тестах подменяются контролируемыми ответами. Такие тесты проверяют обработку данных и ошибок, но не гарантируют доступность сторонних сервисов. Для проверки проекта выполните:

```sh
npm test
npm run build
```

## Переход к рабочему магазину

Для промышленной эксплуатации потребуется серверное API и база данных, серверная авторизация с ролями, общий учёт заказов и остатков, интеграция с учётной системой магазина, платёжным провайдером и уведомлениями. Отдельно настраиваются резервное копирование, мониторинг, хранение фотографий и работа с персональными данными.

Текущий проект позволяет согласовать интерфейс и пользовательские сценарии до подключения этих систем.
